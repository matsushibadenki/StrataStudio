# Macの自動メモリ設定

StudioのRust側が物理メモリ容量を検出し、Metalモデルの準備・再準備完了時とエンジン起動前に、生成済み設定へ次の上限を適用する。

| 統合メモリ | コンテキスト上限 | プロンプト処理単位 |
| --- | ---: | ---: |
| 32 GiB以下・容量取得不可 | 8192 | 64 |
| 32 GiB超〜64 GiB | 32768 | 256 |
| 64 GiB超〜96 GiB未満 | 32768 | 512 |
| 96 GiB以上 | 65536 | 1024 |

環境設定 → エンジンタブの先頭にある固定ツールバーで起動・停止できる。メモリ設定には、物理メモリ・自動値・適用中（停止中は次回起動）の値を表示する。「手動」を選ぶとコンテキスト長、プロンプト処理単位、macOS用の予約メモリを編集できる。「適用」は停止中の保存用。「適用して再起動」は起動中でも編集した値を検証し、停止・保存・起動をRust側でまとめて実行する。次回起動・再準備時にも保存値を再適用する。モデル準備中は編集できず、会話の生成中は一括再起動を実行できない。手動値は自動上限より大きい値も指定できるため、メモリ使用量の増加について情報アイコンで案内する。

`--max-context` と `STRATA_METAL_PROMPT_CHUNK`、`STRATA_METAL_KEEP_FREE_GB` が対象。自動モードでは、外部設定でさらに小さいコンテキスト・処理単位が指定されている場合、その小さい値を維持する。Studioで保存した手動設定から自動へ戻す場合は、自動値へ復帰する。手動指定とStudio適用値を区別するため、生成設定の `studio_metal_memory` に適用値とモードを記録する。Metal以外の設定、モデルパス、他の引数・環境変数は変更しない。メモリの取得に失敗した場合も、実機検証済みの小容量向け設定を使う。

準備コマンドにも容量別コンテキストを渡す。その後に上流セットアップが書いた設定をRust側で調整するため、モデルを再準備しても上流の標準値に戻らない。外部から設定ファイルを再生成した場合も、Studioからの次回起動で適用される。ファイルは同じディレクトリへの一時保存とrenameで更新し、不正な値や保存失敗時は起動・準備完了として扱わずエラーを報告する。

エキスパートarenaの割り当てはエンジンの自動管理を維持する。macOS用の予約メモリは自動時に最大（7 GB、物理メモリの15%）を整数GBに切り上げて使用し、手動時のみ指定値を使用する。既存の外部設定に予約値がある場合は自動時も保持する。実行中のエンジンへの動的な設定変更は行わない。適用値は起動ログと認証付き `/studio/state` の `memoryTuning.active` に表示される。自動推奨値は `memoryTuning.automatic`、保存設定から算出した次回値は `memoryTuning.next` で確認できる。`/studio/inspect` の `metalProfile` は容量別上限を返す。`metalProfile` は容量別上限であり、既存設定の小さい値を維持した場合の実効値は起動ログで確認する。

32 GiBのApple M4で、8K・処理単位64による実チャットを検証済み。その他の容量別設定は境界条件の自動テストで検証しているが、対応する実機での性能・長文負荷試験は ⭕️ [Pending]。8〜24 GiBで推論できることを保証するものではない。利用可能メモリは他のアプリによっても変わる。

手動値の入力範囲: コンテキスト512〜262144、処理単位64〜4096（64の倍数）、予約メモリ4〜256 GBかつ物理メモリ未満。Rust側でも検証し、不正値は保存しない。旧保存データは自動モードで読み込む。

一括再起動はライフサイクルロックで他の起動・停止・準備と直列化する。不正値・モデル準備中・チャット生成中は停止前に拒否する。保存失敗時は以前の設定へ戻して起動を試み、起動失敗時は新しい保存値を保持してエラーを表示する。会話履歴は変更しない。

## リアルタイムの使用量と比較

エンジンタブでMac全体の使用中メモリ・空き（利用可能）メモリ・取得時刻・使用率バーを表示する。RustがMachの `host_statistics64` で取得し、既存の状態ポーリングに合わせ約1.2秒ごとに更新する。複数ウインドウでも計測は1秒間共有キャッシュする。サブプロセスやモデル本体の読み取りは行わない。

利用可能量は、未使用ページ＋破棄可能ページ＋min（inactive＋speculativeページ、file-backedページ）から算出し、物理メモリ容量を上限とする。Strataのarena予算計算と同じ回収可能量の見積もりであり、Activity Monitorの表示定義とは一致しない場合がある。使用中は総容量−利用可能量。エンジン単体の占有量ではなく、他のアプリ・ファイルキャッシュも含む。

通常の「適用」と「適用して再起動」の直前に基準値をRust側で記録し、「変更前」と現在との差分を表示する。「適用して再起動」の場合は停止前に記録する。比較は次のメモリ設定適用まで維持し、アプリ終了時にリセットする。取得できない場合は「取得不可」／「—」とし、0として扱わない。差分は設定変更だけでなく他のアプリやモデルのウォームアップにも影響される。起動・停止処理中は更新が遅れる場合がある。

Strataエンジン単体は、Studioが所有する実エンジンのPIDに対してmacOSの `proc_pid_rusage(RUSAGE_INFO_V2)` から `ri_phys_footprint` を取得する。GUIや子プロセスは含まず、モデルファイルのサイズでもない。Metal等のプロセスに計上される割り当てを含むが、共有・キャッシュの集計はシステム全体と異なる。停止・テストエンジン・取得不能では「—」を表示する。基準値を停止前に記録するので、新しいPIDで再起動しても変更前と比較できる。停止中は基準値のみ保持し差分を出さず、停止中に設定を適用した場合は新しい基準値がないため比較を「—」とする。

## メモリ履歴

Rustのサーバー稼働中、約1秒間隔でMac全体・エンジン単体の値を記録する。チャット画面や環境設定を閉じていても継続する。直近10分（最大620点、イベント最大120件）を共有Stateに保持し、ディスクへは保存しない。アプリ終了時にリセットする。`memoryUsage.history` は時刻・使用量・PID・推論状態、`events` は設定適用・エンジン起動停止・推論開始終了を返す。設定イベントのコンテキスト値は要求値／自動推奨値で、実効値は `memoryTuning.active` を参照する。

エンジンタブのグラフは2・5・10分を切り替え、上下で時間軸を共有する。桁の違う使用量を比較するため縦軸はそれぞれ自動調整し、各段に表示範囲を示す。ホバーで時刻と両方の値を確認できる。紫の帯は推論リクエストの受付からストリーム完了／エラー／切断までで、GPUの実稼働率ではない。チャットと対応API（`/v1/chat/completions`, `/v1/completions`, `/v1/messages`）を記録する。欠測・3.5秒超の計測間隔・エンジンPID変更は線をつながない。短い推論もイベントとして残るが、約1秒未満のメモリピークは捉えられない。
