# Workspace groups and split docking

Chat and Logs can share one tab group or occupy two independent groups. Engine and API remain in Preferences. The Rust layout owns the complete group projection; WebViews render it without owning document state.

## Controls

- Drag a tab onto an edge target (left/right/top/bottom) to dock it as a separate group. Drop onto the center target or the other group's tab to merge. The layout icon next to the tab controls offers the same five placements without dragging; each placement acts on that group's selected tab.
- Drag tabs within a joined group, use the arrow buttons, or press Alt+Left/Right to reorder. Arrow keys and Home/End select tabs in the current group. Cmd/Ctrl+1 and +2 select Chat and Logs by identity and focus the native window that contains the selected tab.
- Drag the split boundary to resize. Arrow keys move it by 5 percentage points; Home/End select the 25%/75% limits. The layout and ratio persist. Narrow windows display side-by-side groups vertically while retaining the saved orientation for a larger window.
- Float either group with its outward-arrow button. Float the second group separately if desired. The dock button, main-window placeholder or normal window close returns a group to its original slot. Repeated Float requests focus the existing window. Floating tabs can dock directly into another floating window or the main workspace, including its placeholders. Drop onto an edge to split or the center/tab to merge. The destination window stays open; empty source windows close automatically. Resetting the whole layout still requires returning floating groups.
- View → Reset workspace layout rejoins Chat and Logs, restores their default order, selects Chat and resets the boundary to 50%.

The group projection currently has a maximum of two groups because there are two workspace tabs. It is not an arbitrary recursive pane tree, and native operating-system drag-out docking is not implemented.

## Shared state and migration

`Document.layout` persists `workspaceOrder`, `workspaceActive`, `workspaceSplit` (`horizontal`, `vertical`, or null) and `workspaceRatio` (25–75). `workspaceGroups` in each snapshot is derived in Rust. `workspaceHosts` maps group IDs to transient native host aliases; a host can render one or both groups after a drop. Host aliases remain stable even when a group is merged or split. A joined group is `workspace`; split groups are `group-chat` and `group-logs`. Every tab appears exactly once. Validated identity-based actions avoid replacing another WebView's unrelated geometry. Old layouts default to a joined group and 50%.

Tauri serializes float/dock operations and checks group membership while holding the document lock before creating a native window. Native docking commits group topology and its transient host map together, then retires empty hosts. The destination is the Tauri window that received the drop, rather than a caller-supplied host label. Stale destination windows are rejected. Destroyed windows clear transient detach flags; these also reset on app restart, while saved split geometry is restored into the main window. Existing conversation, reasoning, metrics, logs, settings and in-flight Rust text remain shared. Docking does not reload the model or copy conversations. An unsent composer draft remains in its originating WebView; normal window close drops its unsent draft and cancels a request initiated there. Direct docking hides a generating source WebView until its stream ends, then closes it, so moving a tab does not cancel generation. The destination Cancel button can signal the source WebView through a native event.

Checks menu bounds and composer fit. Browser plugin not available; Playwright uses installed Chrome. These scripts require an isolated server on 8081 plus Vite on 5180 and reject the native application's 8080 port. Override `STUDIO_TEST_API` / `PLAYWRIGHT_CHROMIUM_EXECUTABLE` if necessary.

Quit/relaunch restored both groups and that ratio with all six original messages, settings and active conversation unchanged. Native merge and View reset also passed; verification layout changes were restored afterward.

The test-only example binds 8081 and authenticates its fixture commands; production studio-server has no fixture endpoints. The browser test transports real dragstart payloads between separate WebViews and calls the actual Rust host transitions. It covers main placeholders, floating-to-floating merge, split within a retained floating host, returning one sibling, native text fallback, malformed payloads and retired-host bookkeeping. Native menu-driven window reconciliation was checked separately: a live Chat stream moved into the floating Logs host, all 60 tokens completed, and a subsequent transferred stream could be cancelled from its destination. Physical macOS cross-window dragging was then verified with user-authorized CGEvent input on the Apple Silicon release build. Trusted native WebKit drops completed floating-to-main right-edge docking, floating-to-floating center merge, and bottom-edge re-splitting inside the retained floating host. Rust host maps confirmed source retirement and destination retention. A native screenshot confirmed the visible destination targets during the held drag. Verification uses the current window bounds and the actual visible target centers; dropping outside those targets leaves the layout unchanged.

All 54 core tests passed. Browser regression checks passed for EN/JA/ZH, light/dark, 1440/390/320 px, native-format drag fallback, split/merge, malformed data, and message preservation. The temporary native fixture engine was stopped and the test conversation deleted afterward; original messages, settings and layout were restored.

Drag previews are transient DOM attributes on the destination slot, with hit targets already mounted. They update in the current native drag event, clear on exit/drop/end and survive WebKit child-boundary dragleave events with null relatedTarget. Capture handlers also accept non-bubbling events, and dragover can restore a destination without another dragenter. The optional authenticated `traceDocking` diagnostic is disabled by default, memory-only, limited to 128 events and excludes message text and drag payload values. It records only bounded event metadata for native verification.
